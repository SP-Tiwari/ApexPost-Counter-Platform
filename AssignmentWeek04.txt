Week-04 part-A 25 marks.


Lab Problem Statement:

Background
ApexPost Logistics now has a central SQL Server database (Week 3). Couriers in the field often lose network coverage but must still record pickups and deliveries. Over the four parts of this week you will build the complete “courier offline → API → mobile app” flow. Part A gives the courier device a local NoSQL store.

Objective
Create a class library named ApexPost.Courier.Offline and a console test harness that store shipment scans as JSON documents in Couchbase Lite. Queries and change notifications must work with no network.

Requirements

Couchbase Lite integration
Add Couchbase Lite to the solution.
Open a local database named apexpost_courier and use its default collection.
Wrap the database in a CourierDatabase class that implements IDisposable.
JSON document model
Store ShipmentScan documents with these fields:
trackingNumber
scanType: Pickup / InTransit / Delivered / Failed
courierId
location
scannedAtUtc
notes
syncStatus: Pending / Synced / Failed
Document IDs must use the format scan::{Guid}.
Repository
Define IScanRepository and implement it as CouchbaseScanRepository.
It must support create, get by ID (key-value lookup), update, delete and list all.
Domain classes must not reference any Couchbase types.
SQL++ queries
All scans for a tracking number, ordered by scannedAtUtc.
All scans where syncStatus = 'Pending'.
Number of scans per scanType for one courier.
Use query parameters only; never concatenate strings into a query.
Create value indexes on trackingNumber and syncStatus.
Offline persistence strategy
Every new scan is saved locally first with syncStatus = Pending.
Create an OutboxService that reads pending scans and marks them Synced or Failed.
In this part the outbox calls a fake IShipmentUploader; Part D replaces it with the real API call.
Change listeners
Register a collection change listener that logs the IDs of changed documents and shows a live “pending scans” count.
Remove the listener token when the database is disposed.
Console harness menu
Add Scan
Find by Tracking Number
List Pending
Simulate Sync
Delete Scan
Exit
Design note (OFFLINE-DESIGN.md, about one page)
Why the app saves locally first.
How conflicts would be handled: last-write-wins vs. the server deciding.
Why an embedded database must not be shared by several processes.
Constraints

Do not change the Week 3 SQL Server / EF Core code.
Couchbase Server and Sync Gateway are not needed.
Use fictional data only.
Deliverables

GitHub repository with branch week4-partA merged.
OFFLINE-DESIGN.md.
Screenshots of the query results and the listener log.
