## First confirmed implementation gap selected for immediate fix

1. Money-order threshold behavior mismatch in `MoneyOrderApplicationService`.

Rationale: explicitly required behavior, localized change surface, and low risk to unrelated workflows.

## Reporting limitation confirmed

Current persisted transaction schema does not store a business date/timestamp usable for date-accurate historical daily sales reporting. The current daily report parameter is therefore not backed by date-filterable transaction data.

A minimal safe future change would add a business-date (or timestamp) field to persisted transactions with backward-compatible repository migration and targeted report filtering tests.

## Remaining high-priority gaps after first fix

1. Missing explicit branch management workflows.
2. Missing explicit staff management workflows.
3. Missing explicit product management workflows.
4. Daily-sales data-model limitation for historical date semantics.
